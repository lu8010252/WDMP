# 弱电工程综合管理与运维平台(WDMP)

极致轻量化的弱电工程综合管理与运维系统。使用 **Go + 原生 SQLite(CGO)+ 零构建步骤原生 JS 前端**实现,
单一二进制文件,空载运行时内存占用约 **14~20MB**,写入压力下一般也在 **30~50MB** 以内,适合小内存 VPS(200MB 级别)部署。

## 技术选型说明

- **后端**:Go 1.22 标准库 `net/http`(无第三方 Web 框架),`mattn/go-sqlite3` 作为 SQLite 驱动。
- **前端**:原生 HTML + CSS + JS,无 React/Vue/Webpack 等构建链,浏览器直接加载,资源体积小、无编译开销。
- **数据库**:SQLite 单文件,WAL 模式,内置一键 `VACUUM INTO` 快照备份。
- **二维码库**:本地内置 `qrcode.min.js`(MIT 协议),无需连接外部 CDN,适合网络环境较差的施工现场。

## 快速开始(Docker Compose,推荐,无需下载源码)

镜像由 GitHub Actions 自动构建(amd64 / arm64 / armv7),发布在 `ghcr.io/lu8010252/wdmp:latest`。
新建一个文件夹,把仓库里的 `docker-compose.yml` 内容存进去,改好 `ADMIN_INIT_PASSWORD` 后:

```bash
docker compose up -d
docker compose logs -f      # 查看日志确认启动成功
```

更新到最新版:

```bash
docker compose pull && docker compose up -d
```

启动后访问 `http://<你的服务器IP>:8080` 即可。

默认管理员账号:`admin`,默认密码:`admin123`(或你在 compose 文件里设置的 `ADMIN_INIT_PASSWORD`),
**首次登录后请立即在"用户管理"中新增自己的账号或重置 admin 密码**。

### 想自己从源码编译

```bash
git clone https://github.com/lu8010252/wdmp && cd wdmp
# 编辑 docker-compose.yml:注释掉 image 行,取消 "build: ." 的注释
docker compose up -d --build
```

## 快速开始(纯 Docker 命令)

```bash
docker build -t wdmp:latest .

mkdir -p ./data

docker run -d \
  --name wdmp \
  --restart unless-stopped \
  -p 8080:8080 \
  -v $(pwd)/data:/app/data \
  -e ADMIN_INIT_PASSWORD=请修改为强密码 \
  --memory=64m \
  wdmp:latest
```

`./data` 目录会包含:
- `wdmp.db` / `wdmp.db-wal` / `wdmp.db-shm`:SQLite 数据库主文件
- `vault.key`:密码本 AES 加密密钥(首次启动自动生成,**务必随数据库一起备份**,丢失后已加密的核心设备密码将无法解密)
- `photos/`:终端设备现场照片(已压缩至 200KB 以内)

## 不使用 Docker,本地直接运行(需要本机已安装 Go 1.22+ 和 gcc)

```bash
CGO_ENABLED=1 go build -tags "sqlite_fts5" -o wdmp .
DATA_DIR=./data ADMIN_INIT_PASSWORD=admin123 ./wdmp
```

## 环境变量

| 变量 | 默认值 | 说明 |
|---|---|---|
| `LISTEN_ADDR` | `:8080` | 监听地址 |
| `DATA_DIR` | `./data` | 数据库、照片、加密密钥的存放目录 |
| `ADMIN_INIT_PASSWORD` | `admin123` | 首次启动时自动创建的 admin 账号初始密码(仅在数据库为空时生效) |
| `COOKIE_SECURE` | `false` | 设为 `true` 后登录 cookie 会带 `Secure` 标志,只允许通过 HTTPS 发送。**前提是你已经在 Nginx/Caddy 等反代层配好了 HTTPS**,否则浏览器会拒绝在 HTTP 页面下写入该 cookie,导致登录后立刻被判定为未登录。纯 HTTP 部署(内网/临时测试)请保持默认值不要开启 |
| `ALLOW_REGISTRATION` | `true` | 是否开放登录页的自助注册。**注册账号默认就能只读查看所有项目的数据(含设备 IP、位置、照片)**,服务暴露在公网时建议设为 `false`,账号由管理员在"用户管理"里创建 |
| `TRUST_PROXY` | `false` | 部署在 Nginx/Caddy/1Panel 反代之后时设为 `true`,登录防爆破限流才会按真实客户端 IP 统计(优先读 `X-Real-IP`,否则取 `X-Forwarded-For` 最后一段)。不设的话所有人共用反代的 IP,一个人输错 5 次会把大家都锁 5 分钟。**仅当 WDMP 端口只对反代开放时才开启**,否则请求头可被伪造 |
| `BACKUP_INTERVAL_HOURS` | `24` | 自动备份周期(小时)。服务启动后会立即先自动备份一次,之后按此周期循环。设为 `0` 可关闭自动备份 |
| `BACKUP_KEEP_COUNT` | `7` | 自动备份最多保留几份,超出的旧备份会被自动删除,避免小磁盘 VPS 被占满 |

## 功能模块

1. **多用户与修改履历**:登录鉴权(管理员/施工人员两种角色),所有新增/修改/删除操作均记录字段级别的变更前后内容,"修改日志"页面可按模块、操作人筛选查询。
2. **工程量与三方数量对比**:按项目录入图纸数量/清单数量/实际安装数量,自动计算差值并用红(漏装)/绿(一致)/黄(多装)颜色标注,支持 Excel 导入导出。
3. **终端设备点位台账**:摄像机/无线AP/广播音响/门禁一体机等分类管理,支持现场拍照(前端自动压缩至 200KB 以内),支持批量勾选生成含二维码的打印标签。
4. **核心密码本**:NVR、服务器、门禁主机、防火墙等核心设备集中管理,登录密码使用 AES-256-GCM 加密存储于数据库,页面默认掩码显示,一键复制到剪贴板(查看行为会被记录进修改日志)。
5. **交换机与网络划分**:交换机及逐端口标记网络属性(内网/外网/监控专网)。
6. **一键备份**:管理员可在"数据备份"页面一键下载完整备份包(.tar.gz,含数据库、密码本密钥 `vault.key`、设备照片),也可在页面里上传备份包恢复。

## 找回密码

如果 admin 账号密码忘记了,不需要重新初始化整个数据库,用下面这个方法找回:

```bash
# 1. 在 docker-compose.yml 的 environment 里临时加一行(或用 docker run -e 临时加)
#    RESET_ADMIN_PASSWORD=你想设置的新密码

# 2. 重新构建/重启一次
docker compose up -d

# 3. 查看日志确认已生效
docker compose logs | grep RESET_ADMIN_PASSWORD

# 4. 用 admin + 刚才设置的新密码登录

# 5. 【重要】登录成功后,把 docker-compose.yml 里 RESET_ADMIN_PASSWORD 这一行删掉,再重新启动一次
docker compose up -d
```

⚠️ 第5步千万别漏:这个环境变量只要还在,**每次重启容器 admin 密码都会被强制改回这个值**,删掉之后才能像平时一样自由改密码。这个方式只能重置 admin 账号,不会影响其他施工人员账号的密码(其他账号忘记密码,直接用 admin 登录后去"用户管理"重置即可)。

## 修改日志清理

日志会一直累积,占用数据库文件的磁盘空间(不影响内存)。管理员可以在"修改日志"页面点击"清理历史日志",指定保留最近多少天,点击后会先弹窗告诉你具体会删除多少条记录,确认后才真正执行,清理这个动作本身也会被记录一条新日志留痕。

## 数据备份建议

除页面内的一键导出功能外,建议在宿主机上对 `./data` 目录做定期快照(如 `rsync` / `cron` + `tar`),
因为 `./data` 中还包含无法通过页面导出的照片文件与加密密钥。

- "网线测距"工具补充了一个重要说明:**100米上限对 Cat5e/Cat6/Cat6a 都一样**,这是标准以太网结构化布线的信道长度规范,跟网线类别无关;类别真正的区别是"能稳定支持的最高速率"。新增"目标速率"选择(千兆/万兆),选万兆时会额外提示:非增强型 Cat6 在干扰较大环境下万兆的实际稳定距离通常只能到约 55 米,超出建议改用 Cat6a 或降速跑千兆。

### v2.2(工具箱新增9个工具,共15个)

新增以下 9 个纯前端速算工具,和之前一样不依赖数据库、不联网也能用:

- **压降计算**:按供电电压、负载电流、单程距离、线径估算末端实际电压,判断是否满足设备最低工作电压(内置常见线径预设)。
- **UPS续航**:按蓄电池容量(Ah×V×节数)和负载功率估算断电后的应急供电时长。
- **线规换算**:AWG线规 ↔ mm² 截面积双向查询(按标准 AWG 公式计算),外加米/英尺/英寸/码长度单位互换。
- **桥架填充率**:按桥架截面尺寸和线缆规格(可分组多种线缆)估算填充率,超过常见 40% 参考值会提示。
- **网线测距**:输入网线长度判断是否接近或超过 100 米标准限制,给出应对建议。
- **镜头视场角**:按镜头焦距和传感器尺寸(内置常见 IPC 传感器尺寸预设)估算水平/垂直/对角视场角,以及指定距离下的画面覆盖范围。
- **线材粗算**:按点位数量和平均单点距离估算总用线量和建议采购箱数(默认整箱 305 米)。
- **密码生成**:生成设备激活用随机强密码(已排除 0/O、1/l/I 等易混淆字符),支持批量生成。
- **RTSP编码**:账号密码含特殊字符(@ : /)时自动做 URL 编码并拼出完整 RTSP 地址,附带反向解码校验功能。

### v2.1(新增工具箱模块)

- 新增"工具箱"导航,收录 6 个弱电工程常用速算工具,**全部纯前端计算,不依赖数据库和网络**,输入即时出结果:
  - **IP规划**:输入 CIDR 网段或"IP+掩码",给出网络地址、广播地址、可用地址范围、建议网关,支持查看可用地址列表(点击复制)、按前缀拆分子网。
  - **带宽评估**:按分辨率/编码分组录入路数和单路码流(内置常见预设),自动合计总码流并与上联带宽比较,超限会有提示。
  - **存储估算**:按路数、码流、存储天数估算录像总容量需求,并给出建议硬盘数量(可设置格式化/预留损耗百分比)。
  - **PoE预算**:按设备分组录入数量和单个功耗(内置 802.3af/at/bt 预设),合计总功耗并与交换机 PoE 总预算比较。
  - **RAID容量**:按硬盘数量、单盘容量、RAID级别(0/1/5/6/10)速算有效可用容量和冗余开销占比,盘数不满足最低要求会有警告。
  - **光衰预算**:按光纤长度、熔接点、活接头估算链路总损耗,与光模块光功率预算比较,判断链路余量是否足够。
- 这几个工具都是纯前端 JS 实现的独立计算器,没有用到任何数据库表,几乎不增加系统资源占用,后续如果需要保存计算历史或加更多小工具,可以在这个模块基础上继续扩展。

- **安装数量登记防呆**:新增/编辑时"设备型号"输入框会自动带出当前项目里已有的设备名称做下拉建议,减少手打型号跟工程量对比对不上导致同步失败的情况。
- 顺带修复一个数据库升级顺序的 bug(新建索引引用了还没加上的字段,导致老数据库升级后启动失败),以及大列表(几百台设备)渲染性能优化(超过200条自动分批显示,点"显示更多"再加载,避免一次性渲染卡顿)。

### v1.4(密码本、交换机关联项目)

- **核心密码本**和**网络与交换机**现在都必须关联到具体项目,页面顶部加了项目筛选下拉框,和其他模块保持一致,不会再出现"不知道这是哪个项目的密码/交换机"的情况。
- 一台设备/一条记录创建后所属项目不可更改(避免跟筛选逻辑冲突),如果录错了项目,删掉重新在正确项目下新建即可。
- 老数据自动迁移保留,但升级前录入的密码本/交换机记录不属于任何项目(项目筛选默认不显示),**需要手动编辑一下重新保存**才能让它们归到某个项目下(内容不会丢,只是需要重新关联)。
- 顺带修复了一个潜在的同类 NULL 字段读取问题(和之前设备照片那次是同一类 bug,这次防御性地统一加固,不会真正影响到你手上的正常数据)。

### v1.3(安装数量登记支持Excel导入导出)

- "现场安装数量登记"页面新增"导出Excel"/"导入Excel"按钮,列为:总分类、子分类、安装位置、设备型号、数量、备注。
- 导入时会按名称自动查找/创建总分类和子分类(和设备台账、工程量对比的导入逻辑一致),每一行导入后都会触发一次同步,自动累加到"工程量对比"对应设备的实际数量。

### v1.2(新增到货数量)

- **工程量对比**新增"到货数量"字段,和图纸/清单/实际数量并列,可直接编辑,也支持 Excel 导入导出。
- 新增两个自动对比:"到货-清单"(用来看材料有没有到齐,到货不足会标红)、"实际-到货"(用来看有没有出现"装的比到的还多"这种异常情况,正常应该 ≤0)。
- 老数据库升级后会自动加上这一列,已有的工程量条目到货数量默认是 0,后续按需手动填写即可,不影响原有数据。

### v1.1(新增两级分类 + 安装数量登记)

- **分类管理**:新增"分类管理"模块,设备台账、工程量对比、安装数量登记三个模块统一使用"总分类 + 子分类"两级结构,可自行新增/编辑/删除(删除总分类会级联删除其子分类,已被引用的记录不受影响)。
- **现场安装数量登记**:新增模块,选好分类后可一次性登记"安装位置 + 设备型号 + 数量",不需要像设备台账那样逐台录入 IP/MAC 等详细信息。
- **自动同步**:安装数量登记的数量会自动汇总,写入"工程量对比"里对应设备(按 总分类+子分类+设备名称 匹配)的**实际安装数量**;如果工程量对比里还没有这条设备,会自动创建一条。
- **重要提示(如果你在这次更新前已经录入过设备/工程量数据)**:老数据会自动迁移保留,但由于以前是自由文本分类,系统无法自动猜出应该对应到新的哪个分类,**升级后请到"分类管理"先建好总分类/子分类,然后逐条把老设备/老工程量条目重新指定一下分类**(分类字段之前的内容仍会作为文字保留展示,不会丢失,只是需要重新关联到结构化分类)。
- **顺带修复了一个从最初版本就存在的 bug**:设备台账里,如果一台设备还没上传过现场照片,它在"实际数量列表"接口层面会被数据库判定为异常行,导致这台设备无法在列表中正常显示,也无法编辑或删除,而且用 Excel 批量导入的设备也会中招。现在已修复,不管有没有照片都能正常显示、编辑、删除;如果你之前已经部署过并遇到过"设备录入后突然消失/编辑不了"的情况,更新后重新构建即可自动修复,老数据不需要额外处理。
